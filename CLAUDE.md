# CLAUDE.md

Sarv India (mink blanket manufacturer) ERP: a set of static HTML/JS apps on a shared Supabase backend
(`https://jdlzgjgxxjkjejkhvdij.supabase.co`). No build step, no package manager, no tests. Files open
directly in the browser (also over `file://`) or are served as static files from one origin.

`README.md` is the detailed feature/setup reference. Read the relevant section before
changing a feature. Note: the README and older comments say `Store.html`; that file is now `index.html`.

## Desktop ERP script order — do not change

```
index.html <head>: date-dmy.js → caps-input.js → hover-tip.js → sso-preboot.js → sso-gate.js → store.css → erp-shell.css → store-mytasks.css
end of <body>:     store-core.js → store-design-master.js → store-nav-keys.js → store-mytasks.js → erp-shell.js → app-back.js
```

- These are **classic scripts sharing one global lexical scope**: later files read top-level `const`/`let`
  from `store-core.js` directly (`SB`, `SB_READY`, `escText`, `fetchAllRows`, `sarvCurrentRole`, …).
- Never add `type="module"` or `defer` (breaks shared scope, `file://` CORS, and ordering).
- `erp-shell.js` must load after `store-core.js`: it wraps `sarvGoHome` / `sarvNavigateFromHome` /
  `activatePanel` at window level and never patches `store-core.js`. Sidebar leaves just click the
  original (hidden) home-tile buttons by their `data-go` key. Removing `erp-shell.css` + `erp-shell.js`
  restores the old tile home.
- `store.css` rule order is load-bearing; don't reorder.

## Auth / single sign-on

- Same name, different people (`sql/FIX_USER_SAME_NAME.sql`): two employees of one name may share a role when their Emp Codes differ (unique index `app_users_role_name_emp_uq` on role + name + emp code, `admin_save_user` USER_EXISTS and the Admin Panel user form use the same rule); a PURCHASER name stays unique (`app_users_purchaser_name_uq`), because the purchaser's PIN key and every PR / PO find them by name.
- One user table: `public.app_users` (`role` = primary role used for signatures/audit; `roles text[]` = access
  union). In code: `sarvCurrentRole` (primary), `sarvCurrentRoles`, `sarvRoles_()`.
- `launcher.html` → `erp_app_login()` creates an `app_sessions` token stored in localStorage
  (`sarv_sso_token`); every app reads it.
- `sso-preboot.js` (first in `<head>`): if a token exists, hides login overlays and shows a splash
  synchronously; each app must call `sarvSsoPrebootDone()` on every path (9 s backstop).
- `sso-gate.js`: `SARV_GATE.boot({url, key, app, label, client, needAuth, accountKey})` checks session,
  app access and app account; it resolves only on success, otherwise redirects to the launcher or shows a
  reason screen (`WHY` codes like `NO_APP_ACCOUNT`, `SESSION_REVOKED`). No app has its own login form —
  don't add one.
- Complaint/Packing need a real Supabase Auth session, minted by the `erp-sso` Edge Function
  (`supabase/functions/erp-sso/`, not in this folder) via magic-link OTP.
- `app-back.js`: floating "← Apps" button, auto-hidden inside ERP iframes, on the launcher, or without a session.
- Access precedence: per-user `app_access` override (ON/OFF; the Users › Apps form has no "auto" any more, a missing key still falls through) → role-wise Tab Visibility matrix → code default. New users start with `SARV_NEW_USER_OFF` apps OFF (`NEW_USER_APP_DEFAULTS_MIGRATION.sql` for signups).

## Database changes

SQL migrations (`*_MIGRATION.sql`, `CHECK_*.sql`, `FIX_*.sql`) and `supabase/` are **not in this folder**;
the README lists them and their required run order. They're run manually in the Supabase SQL Editor and are
written to be idempotent. Code typically degrades gracefully when a migration hasn't run (banner/console
warning rather than failure) — preserve that pattern. Some features intentionally store data in existing
jsonb columns to avoid migrations (e.g. PO follow-ups in `purchase_orders.approvals.followups`, append-only).

## Conventions

- Plain vanilla JS with inline `onclick` handlers and global functions; ERP helpers are prefixed `sarv…`
  (private ones end in `_`), feature-local prefixes (`dm`, `fbm_`) avoid id/class collisions.
- Comments and user-facing strings are in plain Indian English (they were translated from Hinglish; a copy
  of the pre-translation files is in `_backup_before_english/`). Comments explain *why*, often at length;
  keep that density. Deliberate exceptions: the Devanagari `hindi=` labels in `complaint.html` (bilingual by
  design), the Hinglish search synonyms in `erp-shell.js` `QN_WORDS` (search data), and the `hisaab` data
  keys in `trims-manager.html`.
- No emojis in the UI. Icons are inline SVG line icons (`I.*` in `erp-shell.js`, inline `<svg>` in
  `launcher.html`); small table actions use text labels or plain glyphs (✎ ✕ ✓ ↻ ☰ ▾). Prefer flat fills,
  thin borders and light shadows over gradients and glows.
- Always escape user data with `escText()` when building HTML strings.
- Every search box / filter in the desktop ERP uses `sarvSearchMatch(hayStringOrArray, typedText)` (top of
  `store-core.js`): Google-style, every keyword anywhere in any order, `"phrase"`, `-exclude`, `a OR b` / `a|b`,
  punctuation ignored inside a word. Use it for new search boxes instead of `.includes(q)`; `sarvSearchTerms(q)`
  gives the words to highlight.
- `caps-input.js` (every app page except `launcher.html`, right after `date-dmy.js`) shows and saves all typed
  text in CAPITALS. It skips password/email/url/number/date inputs, `data-dmy` boxes, read-only boxes and any
  box named as a PIN/password/OTP/token/email/mail/url field; mark a container `data-no-caps` to opt out.
  Keep name/item lookups case-insensitive (`ilike` / lower-cased compare) so capitals never create duplicates.
- `hover-tip.js` (every app page except `launcher.html`, right after `caps-input.js`; before `sso-preboot.js` in
  Yarn Unloading / Catalog Maker): one mousemove listener that shows its own small tooltip (`role=tooltip` div,
  not `title`) with the full text of any box, dropdown, cell, list item or `.truncate` block whose text is cut off.
  Disabled text boxes get `pointer-events:none` (injected style) so their cell gets the mouse and the box under the
  pointer is found by position: Chrome shows no native tooltip on a disabled box. An unlocked element with its own
  `title` keeps it; PIN / password boxes are skipped. A new app page should load it too.
- Dates: every app loads `date-dmy.js` first, which turns `<input type="date">` into a DD/MM/YYYY text box
  (`data-dmy="1"`) whose `.value` still reads/writes `YYYY-MM-DD`. Select date boxes with
  `input[type=date],input[data-dmy]`. Use `today()` (local date), never `toISOString().slice(0,10)` for "today".
- `offline-sync.js` is the FIRST script in <head> of every app page (before supabase-js / `sso-gate.js`, which capture `fetch`). APK only (`Capacitor.isNativePlatform`; browser opt-in localStorage `sarv_offline_web=1`): wraps `fetch`, saves every Supabase read (GET/HEAD `/rest/v1`, RPCs NOT matching its `WRITE_RPC` regex) in IndexedDB `sarv_offline`, replays it when offline / after 9 s, never replays writes, clears on `erp_app_logout`, and draws the top pill `Online · Sync Live` / `Offline · Last sync ...` (iframes report to the top window). A new WRITE RPC whose name does not match `WRITE_RPC` must be added there. CDN libs are cached natively by `android/.../CdnCacheWebViewClient.java` (set in `MainActivity`). A new app page should load it too.
- Task Manager › PC Follow-up **Notify** (one employee: `pcNotifyOne`, button in the pane; everyone listed with pending: `pcNotifyAll`): phone push via `tm_notify(p_token, p_items)` (`sql/TM_NOTIFY_MIGRATION.sql`, right TM_PC_FOLLOWUP or TM_LATE_APPROVE, 2-min cooldown per employee, log `tm_notify_log`, send key in Vault `sarv_send_key`, pg_net → Edge Function `push-send`). Never put the send key in a page. Tap opens `task_manager.html#my-tasks`. **Rings until Confirm** (`sql/TM_NOTIFY_ALARM_MIGRATION.sql`): tm_notify sends `alarm:true` + `data.alarm_id` (= `tm_notify_log.id`); `push-send` sends a DATA-only `type:alarm` message to tokens with platform `android-alarm` (saved by `push-register.js` when the native `SarvAlarm` plugin exists), a normal notification to older APKs. Native: `SarvMessagingService` (replaces the plugin FCM service, manifest `tools:node=remove`) → `AlarmService` (foreground, looping ring at ALARM volume + vibration, 10-min safety stop) + `AlarmActivity` (full-screen CONFIRM) → `MainActivity` opens the page with `?notify_ack=<ids>` → `push-register.js` calls `tm_notify_ack`; PC chip shows Confirmed / Not confirmed yet (`tm_notify_last.acked`).
- **Auto pending-task reminder (APK, offline)**: after every `loadData` in `task_manager.html`, `tmSyncReminders` hands the logged-in user's own task deadlines (today + 2 days; not done / moved / day off; personal tasks left out) to the native `SarvAlarm.setReminders` (SharedPreferences). `ReminderReceiver` (exact alarm every 15 min, re-armed on boot / update) rings `AlarmService` while any of TODAY's is past its deadline, 08:00-20:00 only, skipped while another alarm rings. Empty list = off; `push-register.js` clears it when there is no session. Done-state is as of the last sync.
- **iOS motion / touch / speed layer** (`ios-ui.css` + `ios-ui.js`, in every external app page, after the page's own head scripts; `mobile.html` has the fuller `mobile-ios.*` pair): never changes layout or colours, only how a page moves and is touched (its CSS rules that could clash use `:where()`, so the app's own CSS wins). It gives lazy `<img>` (`loading=lazy decoding=async`, skipped for `data:` / `blob:` and `[data-no-lazy]`, eager while printing), a spring fade / pop (sheet on a phone) for overlays that appear (`window.IOS_UI={overlays:false}` before the script switches it off: task_manager does, its modals animate themselves), link prefetch on touch / hover, and `window.IosUI` (`slider`, `pullToRefresh`, `skeleton`, `cardsIn`, `lazyList`, `prefetch`, `idle`). Each page also has `<link rel=preconnect>` hints for its own hosts. Page skins (task_manager frosted bar / screen fade / home buttons rising, launcher tile press + idle prefetch of its first apps, complaint) sit in each page's own style block. **complaint.html compile cache**: its JSX is in `<script type="text/plain" id="cmp-src">`; the loader at the end keeps the compiled JavaScript in IndexedDB (`sarv_cmp_cache`) under a hash of the source, so Babel (~3 MB) loads only when the source changed. Edit the JSX as before; the hash changes and it recompiles once. Bump the `?v=` of the two files when either changes.
- **Dropdown lists** (`ios-dropdown.css` + `ios-dropdown.js`, in EVERY app page: right after `ios-ui.css` / `ios-ui.js` (defer); `index.html` css after `store-mytasks.css`, js after `upload-guard.js`; `mobile.html` after `mobile-ios.*`; a new page must load the pair; bump `?v=` when either changes): the browser's own `<select>` and `<input list>` (datalist) popups are replaced by the Gate-2 search-list card (`.gate-combo` look, class prefix `iosdd-`) opening with an iOS spring: a popover under / over the box on PC / tablet, a bottom sheet on a phone (< 768 px: grabber, label as title, Done, pull down / tap outside to close); Search box from 9 options, optgroup headers, the chosen row ticked. Event delegation on document (pointerdown / touchend tap / Space · F4 · Alt+↓ on a focused select), so boxes added later need nothing; options are read at open and followed by a MutationObserver while open. The pick is written through the element's own value setter + `input` + `change` (inline onchange, listeners and React all see it). A datalist box's `list` attribute is parked in `data-iosdd-list` while focused (no native popup) and put back on blur unless the page removed it / locked the box. Skipped: disabled / read-only boxes, `select[multiple]` / size > 1, `[data-native]` / inside `[data-native-dd]`. Gate-2's own `.gate-combo` lists get the same entrance animation. `window.IOS_DROPDOWN = {selects:false | datalists:false}` before the script switches a part off; `IosDropdown.open(el)` / `.close()`.
- **iOS dialogs** (`ios-dialog.css` + `ios-dialog.js`, in EVERY app page next to the dropdown pair; the js NOT defer, so it is in place before the page's own code; a new page must load it): `alert()` / `confirm()` / `prompt()` become an iOS alert (frosted 270 px card, first line = title, hair-line buttons, preferred bold, a delete / cancel / reject … confirm gets a red OK; alerts queue one after another). `alert` does not wait. `confirm` / `prompt` reached from a user action (trusted click / dblclick / submit / change / Enter keydown, or an event marked `__iosdlg`, as ios-dropdown.js marks its picks) answer Cancel at once, show the box, and on OK REPLAY that action (same target, same event type; a checkbox / select is put back first) with the answers in `CUR.chain`, so `if (!confirm(..)) return;` code runs as before; several boxes in one action are asked one by one. Outside a user action (after an await, a timer) the browser's own box stays. So a confirm whose Cancel DOES something must use `await IosDialog.choose(msg, [{label, value, bold, red, cancel}])` (done for Task Manager › Consult Letters › Save as format). New code: `IosDialog.alert / confirm / prompt / choose` (Promises), `IosDialog.native.*` = the browser's. `window.IOS_DIALOG = {native:true}` keeps the browser's boxes on a page. Page popups in the same look: ERP `showToast` banners + `.sarv-ov` cards (`ios-skin-erp.css`, loaded last in index.html, overrides only), Task Manager `showCustomModal` (style block after ios-dialog.js in its head), HR `openModal` (`.mbg` / `.mdl` rules), FMS `.dlg-back` / `.dlg` (end of fms.css), and `class="ios-toast"` (+ `ios-toast-tr` when the page toggles `show`) on the `#toast` of HR / Issuer / SOP / Order Form / Trims (HR's `toast()` keeps the class).
- **Upload control** (`upload-guard.js`, in EVERY app page right after `sso-gate.js` (else after `offline-sync.js`); in `index.html` last, after `app-back.js`; a new page must load it too): the Admin's rules for every `<input type=file>` of the project, set in ERP › Admin Panel › **Uploads** (UPLOAD CONTROL section at the end of `store-core.js`, `sarvUpLoad_` / `sarvUpRender_` / `sarvUpSave_`, Admin PIN). Key = `<page>#<data-up>` else `#<id, digits → N>` else `#<onchange function>` else `#<label slug>`; a Camera + Gallery pair of one purpose MUST share a key (same `data-up` or same onchange function), so give a new pair a `data-up`. The guard reports every box it sees (`up_register`), so a new box appears in the Admin list by itself, starting with what its code offers (nothing changes until the Admin sets it); it only steps in on a click when the rule differs (wrong way → the allowed way, both ways on a single box → a "Choose from files / Take photo" sheet, nothing allowed → blocked toast) and hides the `<label>` button of a switched-off way in a pair. Server `sql/UPLOAD_POLICY_MIGRATION.sql` (`upload_points` + `upload_point_log`, RLS no policies; `up_policy_list` (no token, cached in localStorage `sarv_up_policy_v1`, refreshed every 10 min) / `up_register` / `up_admin_list` / `up_policy_save`, NEED_ONE = Files or Camera must stay on; a box without pictures is files only), tests `sql/tests/UPLOAD_POLICY_TEST.sql`.
